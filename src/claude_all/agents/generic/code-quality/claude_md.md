### `code-quality` (Haiku) — lint / type-check runner (report-only)
| `ruff`, `mypy`, `eslint`, `prettier`, `tsc --noEmit`, `prek`, `pre-commit` — run gates and report findings | `code-quality` |
⛔ `Bash(ruff check ...)`, `Bash(mypy ...)`, `Bash(eslint ...)`, `Bash(prek run ...)` inline. In any project with `prek.toml` the ONLY valid lint command is `prek run --all-files` — individual tool runs bypass the chain ("ruff passed" ≠ "prek passed": typos, gitleaks, markdownlint may still fail).
Note: reports only; to FIX findings use `lint-fixer`. Full method → the `prek` skill.
⚠️ Running the gate MUTATES the tree even though the agent is report-only: prek's auto-fixing hooks (`ruff --fix`, `ruff-format`, `trailing-whitespace`, `prettier --write`) rewrite files as a side effect, potentially far outside your diff. The agent must return a `[FILES MODIFIED BY THE GATE]` section (`none — working tree unchanged` when clean) — **read it every time** and revert what you didn't intend (`git restore -- <paths>`). If a report ever says "Key Fixes Made"/"Fixed X", treat it as a bug in the run: the agent never fixes, and `git status` before/after is the ground truth.
