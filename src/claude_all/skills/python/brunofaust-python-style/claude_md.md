## Python style — `brunofaust-python-style` skill
**Invoke the `brunofaust-python-style` skill (via the Skill tool) when writing or editing Python (`*.py`) files** — load it, don't just lean on the summary below. The quick rules here are a reminder, not a substitute: for any non-trivial Python work read the skill's matching `references/<topic>.md` (type-hints, error-handling, async-patterns, class-design, config, testing) before the edit.

Rule: editing `.py` → load this skill first. Skipping straight to the edit on the strength of the inline summary is the anti-pattern this prevents.

Quick rules (full set lives in the skill): Python 3.11+ syntax (pipe unions, `asyncio.TaskGroup`, `match`); strict type hints (`Literal`, `@overload`); `structlog` not `logging`; async-first; **`contextlib.suppress(Exception)` PROHIBITED** — use narrow `except SpecificError` with explicit logging; `domain/features/integrations/aws_resources` layout.

**A `dict` never carries a contract.** `TypedDict` and `typing.cast` are **BANNED**: a TypedDict validates nothing at runtime, so `cast(row_dtype, dict(row))` is a no-op that only pretends to type while mypy stays green. Every payload crossing a boundary is a Pydantic model with `extra="forbid"`. The bug class is **not** the `.get(k, default)` spelling — that is a symptom. It is **a default on a field that is required**. → `references/data-modeling.md`

### When a gate fires, fix the contract — never widen the gate

Every finding has one real fix, and one tempting fake fix that makes the message vanish while the bug survives. **The fake fix is never acceptable** — not "for now", not "to unblock", not "the baseline can hold it".

| Gate / symptom                                    | Fix                                                                                                       | ❌ Never                                                                                                              |
| ------------------------------------------------- | --------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `extra-forbid`, or a `ValidationError` on an unknown key | The key was renamed or the schema moved — update the code. A schema change **must** force a code change.  | **relax to `extra="ignore"`** (or `"allow"`). The unknown key silently vanishes and you learn nothing — that re-arms the exact bug the model was added to catch. |
| `masking-default`                                 | Decide the contract. Required ⇒ delete the default, let it raise. Optional ⇒ `T \| None = None`, handle `None`. | add a "safe-looking" default (`""`, `0`, `[]`, `"task"`) — that **is** the original bug, in Pydantic clothing.        |
| `opaque-annotation`                               | Model the shape — `Sequence[Model]`, or a concrete value type.                                             | widen to `Any`, drop the annotation, or `# type: ignore` it.                                                          |
| `no-typeddict` / `no-cast`                        | `Model.model_validate(...)` — *prove* the type instead of asserting it.                                    | `cast()` into a TypedDict. That no-op is where this whole rule came from.                                             |
| `select-star`                                     | Name the columns. `extra="forbid"` is only safe because the query built the shape.                        | keep `SELECT *` and loosen the model to match.                                                                        |
| checker exits **2** (a file would not parse)      | Pin `language_version` on that hook — its env is older than the project.                                   | re-add a `except SyntaxError: return []` fail-open, or exclude the file. A file the gate could not read is a file it did not check. |
| *any* of the above                                | Fix the code.                                                                                             | `--select` the rule away, `SKIP=`, `--no-verify`, `# noqa`, or baseline a **new** finding.                            |

**e2e tests verify REQUIREMENTS; unit tests verify CODE.** An e2e/integration test asserts the *business need*, not the implementation — derive every e2e test from the **requirements**, not from reading the code: the initial prompt + brainstorming iterations + the plan/tasks agreed *before* the coding phase. You may read the code to learn how to drive it, but the assertion comes from "does the user get what they asked for?" — never from "what does the code happen to do?". A test that passes only because it mirrors the implementation verifies nothing about the requirement; pin code internals in unit tests instead. Full method → the skill's `references/e2e-testing.md` + `references/testing.md`.
