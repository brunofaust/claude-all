## Response style — concise & checkpointed

- **One focused change per turn; keep responses short.** Large audits, multi-file refactors, and repo-wide sweeps blow the output-token limit and lose the whole response mid-flight. Split them into steps and commit after each so a hit limit never loses progress.
- **Summarize, don't dump.** Quote only the lines that matter (verbatim, for evidence); never paste whole file bodies or full command output into a reply.
- Prefer a tight summary + quoted evidence over narration — a table or short list beats prose.
