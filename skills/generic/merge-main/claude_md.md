## Merging origin/main — use the `/merge-main` workflow
When pulling origin/main into the current branch ("merge main", "sync with main", "pull origin main and merge", or bringing in work another parallel session just landed on main), run **`/merge-main`** instead of a bare `git merge origin/main`. A clean textual merge can still be semantically broken (main touched a file this branch deleted, changed a contract this branch still calls, or removed a symbol this branch references). `/merge-main` runs the semantic conflict pass **before** the merge — previewing with `git merge-tree` so the working tree stays untouched while you decide — then merges with `--no-commit`, runs the lint/test gates, and only finalizes after they pass. It is a local merge only — it never pushes or opens a PR (that's `/ship-pr`).
