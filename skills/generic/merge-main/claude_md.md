## Merging origin/main — use the `/merge-main` workflow
When pulling origin/main into the current branch ("merge main", "sync with main", "pull origin main and merge", or bringing in work another parallel session just landed on main), run **`/merge-main`** instead of a bare `git merge origin/main`. A clean textual merge can still be semantically broken (main touched a file this branch deleted, changed a contract this branch still calls, or removed a symbol this branch references). `/merge-main` checks the incoming change semantically **before** merging (previewing with `git merge-tree` so the working tree stays untouched), then merges with `--no-commit` and resolves **both** textual and semantic conflicts, validating the result with the lint/test gates before finalizing. Calling it is the decision to merge — it only stops to ask on huge or high-risk differences. It is a local merge only — it never pushes or opens a PR (that's `/ship-pr`).
